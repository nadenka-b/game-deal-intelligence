# Game Deal Intelligence

## 1. О проекте

**Game Deal Intelligence** — это проект по сбору, хранению и анализу данных о скидках на видеоигры.

Основная задача проекта — автоматически получать информацию о предложениях из разных игровых магазинов, отслеживать изменения цен и предоставлять данные для аналитики и визуализации.

В качестве основного источника данных используется CheapShark API.

Проект реализует ETL-процесс: извлечение данных из API, сохранение исходных ответов, преобразование данных в структурированную модель PostgreSQL и подготовку аналитических представлений для Apache Superset.

## 2. Используемые технологии

| Технология | Назначение |
|---|---|
| Python | Извлечение данных и логика обработки |
| Apache Airflow | Оркестрация и планирование пайплайнов |
| PostgreSQL | Хранение данных и выполнение SQL-трансформаций |
| SQL | Преобразование и загрузка данных |
| Docker | Контейнеризация и запуск окружения |
| CheapShark API | Источник информации об играх и ценах |
| Apache Superset | Аналитика и визуализация данных |

## 3. Общая архитектура

В проекте используется трёхслойная архитектура хранения данных на основе отдельных схем PostgreSQL:

- **RAW** — хранение исходных ответов API и информации о запусках пайплайнов.
- **CORE** — хранение структурированных данных об играх, магазинах и предложениях, включая историю изменения цен.
- **MARTS** — слой аналитических представлений и наборов данных.

## 4. Слои данных

### 4.1. RAW

Схема `raw` предназначена для сохранения исходных данных и информации о выполнении пайплайнов.

Основные таблицы:

- `raw.pipeline_runs` — информация о запусках пайплайнов: время начала и окончания, статус выполнения и сообщение об ошибке.
- `raw.raw_api_responses` — исходные ответы API в формате JSONB, связанные с соответствующим запуском пайплайна.

Этот слой обеспечивает возможность отслеживать выполнение загрузок, анализировать ошибки и обращаться к исходным данным.

### 4.2. CORE

Схема `core` содержит структурированные данные, используемые в проекте.

Основные таблицы:

- `core.games` — информация об играх: название, дата выхода, оценки Metacritic и Steam, ссылка на изображение.
- `core.stores` — информация об игровых магазинах и контрольные точки синхронизации.
- `core.deals_current` — актуальные предложения для каждой пары «игра — магазин».
- `core.deals_price_history` — предыдущие состояния предложений, сохраняемые при изменении цен.

Разделение актуальных предложений и истории позволяет анализировать изменения стоимости игр во времени.

### 4.3. MARTS

Схема `marts` предназначена для хранения аналитических представлений и наборов данных, построенных на основе слоя CORE.

Эти объекты предоставляют удобный интерфейс для построения отчётов и визуализаций в Apache Superset.

## 5. Стратегия загрузки данных

В проекте используются два подхода к загрузке данных.

### Первоначальная загрузка (Initial Load)

Первоначальный пайплайн заполняет базу данных доступной информацией из источника.

Он создаёт начальный набор записей об играх, магазинах и предложениях, необходимых для последующей инкрементальной синхронизации.

### Инкрементальная синхронизация (Incremental Sync)

Инкрементальный пайплайн периодически проверяет изменения в данных магазинов и загружает предложения из тех магазинов, которые требуют синхронизации.

После получения данных обновляется слой CORE. Предыдущие состояния предложений архивируются при обнаружении изменения цен.

Такой подход позволяет сократить количество ненужных API-запросов и поддерживать историю наблюдаемых цен.

## 6. Отслеживание истории цен

История цен хранится отдельно от таблицы актуальных предложений.

- `core.deals_current` содержит последнее известное состояние предложения.
- `core.deals_price_history` хранит предыдущие наблюдаемые состояния.
- Исторические записи связываются с запусками пайплайнов через поле `run_id`.

Такая модель позволяет анализировать изменение цен и сравнивать текущую стоимость игры с ранее зафиксированными значениями.

## 7. Визуализация данных

Для аналитики и визуализации используется Apache Superset.

Superset подключается к PostgreSQL и использует аналитические наборы данных из схемы `marts`.

Основные аналитические задачи:

- Сравнение актуальных цен на игры в разных магазинах.
- Поиск наиболее выгодных предложений.
- Анализ исторических изменений цен.
- Изучение динамики скидок.

## 8. Цели проекта

Основные цели проекта:

1. Разработать автоматизированный процесс загрузки данных.
2. Реализовать первоначальную и инкрементальную загрузку.
3. Организовать хранение актуальных и исторических данных о ценах.
4. Обеспечить отслеживание выполнения пайплайнов.
5. Подготовить аналитические данные для визуализации.
6. Продемонстрировать практические навыки Data Engineering с использованием Python, SQL, PostgreSQL и Apache Airflow.

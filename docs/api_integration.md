# Интеграция с API (API Integration)

## 1. Общая информация

В качестве основного источника данных проекта Game Deal Intelligence используется **CheapShark API**.

API предоставляет информацию об игровых магазинах, играх и доступных ценовых предложениях.

Взаимодействие с API реализовано на Python и выполняется в рамках ETL-пайплайнов, оркестрируемых Apache Airflow.

Полученные ответы сохраняются в PostgreSQL, в схему `raw`, до выполнения дальнейших преобразований.

## 2. Используемый API

**Источник:** [CheapShark API](https://apidocs.cheapshark.com/)

API используется для получения следующих категорий данных:

| Категория | Назначение |
|---|---|
| Магазины (Stores) | Получение списка игровых магазинов и информации об изменениях |
| Предложения (Deals) | Получение доступных предложений и информации о ценах |
| Игры (Games) | Получение информации об играх, связанной с предложениями |

Фактический набор используемых endpoints определяется реализацией Python-модулей проекта.

## 3. Взаимодействие с API

Для взаимодействия с CheapShark API используется Python.

Общая последовательность работы:

1. Формирование HTTP-запроса.
2. Отправка запроса к API.
3. Получение ответа.
4. Проверка результата запроса.
5. Сохранение исходного ответа в PostgreSQL.
6. Передача данных на последующую обработку.

Для повторно используемых операций взаимодействия с API используется общий модуль проекта.

Это позволяет избежать дублирования логики запросов в разных DAG.

## 4. Получение информации о магазинах

Информация о магазинах используется для определения необходимости инкрементальной синхронизации.

В рамках Incremental Sync пайплайн получает информацию об изменениях магазинов.

Полученные временные отметки сравниваются со значениями `last_change_unix`, сохранёнными в `core.stores`.

На основании сравнения определяется список магазинов, предложения которых необходимо обновить.

После успешной обработки данных контрольные точки синхронизации обновляются.

## 5. Получение предложений (Deals)

Предложения содержат информацию о доступных ценах на игры в различных магазинах.

Полученные данные используются для формирования записей в `core.deals_current`.

В рамках инкрементальной загрузки предложения запрашиваются только для магазинов, требующих синхронизации.

### 5.1. Пагинация

Для получения большого количества предложений используется постраничная загрузка данных.

Каждый полученный ответ может сохраняться отдельно в `raw.raw_api_responses`.

В таблице сохраняются:

- `page_number` — номер страницы.
- `page_size` — размер страницы.
- `count_result` — количество полученных результатов.
- `payload` — исходный ответ API.

Это позволяет отслеживать процесс загрузки и сохранять отдельные страницы исходных данных.

## 6. Сохранение исходных ответов

Все полученные ответы API сохраняются в таблице `raw.raw_api_responses`.

Каждая запись содержит ссылку на соответствующий запуск через `run_id`.

Основные сохраняемые атрибуты:

| Поле | Назначение |
|---|---|
| `run_id` | Связь с запуском пайплайна |
| `source` | Идентификатор источника или типа запроса |
| `loaded_at` | Время сохранения ответа |
| `page_number` | Номер страницы |
| `page_size` | Размер страницы |
| `count_result` | Количество результатов |
| `payload` | Исходный JSON-ответ |

Сохранение RAW позволяет сохранить первоначальное представление данных, полученных от API, и использовать его при анализе ошибок или проверке результатов трансформаций.

## 7. Обработка ограничений API

При работе с внешним API необходимо учитывать ограничения на количество запросов.

В частности, HTTP 429 (`Too Many Requests`) означает, что сервер ограничил частоту запросов.

В проекте предусмотрена обработка ситуации, когда получение данных завершается из-за ограничения API.

В случае частичной загрузки:

- Уже полученные ответы сохраняются в RAW.
- Полностью загруженные магазины могут быть обработаны.
- Незавершённые магазины не должны получать новую контрольную точку синхронизации.
- Запуск может завершиться со статусом `partial`.

Это позволяет повторно обработать незавершённые магазины при следующем запуске.

## 8. Управление подключением

Для хранения параметров подключения к API в Apache Airflow используется Connection:

`api_cheapshark`

Это позволяет отделить параметры подключения от логики DAG и не хранить их непосредственно в исходном коде пайплайнов.

## 9. Возможности для дальнейшего развития

В дальнейшем интеграцию с API можно расширить:

- Добавить дополнительные источники данных.
- Интегрировать RAWG API для получения расширенной информации об играх.
- Реализовать дополнительные проверки качества входящих данных.
- Расширить обработку ошибок и ограничений API.
- Добавить мониторинг доступности источников данных.
